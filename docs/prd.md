# PRD — เว็บไซต์ชมรมอาสาพัฒนา

> ไฟล์นี้ยังเป็นโครง — กรอกรายละเอียดจริงของชมรมก่อนสั่งให้ tech-lead ออกแบบสถาปัตยกรรม
> ยิ่ง PRD ชัด agent ยิ่งแม่น อย่าประหยัดเวลาตรงนี้

## 1. ชมรมทำอะไร
(อธิบายสั้น ๆ ว่าชมรมนี้คืออะไร ทำกิจกรรมประเภทไหน)

## 2. บทบาทผู้ใช้ (Roles)
- **สมาชิกทั่วไป**: สมัครสมาชิก, ดูข่าว/กิจกรรม, สมัครเข้าร่วมกิจกรรม, ตั้งค่าการแจ้งเตือน
- **ผู้ดูแล (editor)**: เพิ่มเติมสิทธิ์เขียน/แก้ไขโพสต์และกิจกรรม
- **ประธานชมรม/admin**: สิทธิ์เต็ม จัดการสมาชิกและตั้งค่าระบบ

(ปรับบทบาทให้ตรงกับโครงสร้างชมรมจริง)

## 3. ฟีเจอร์หลัก (MVP)
1. สมัครสมาชิก + ยืนยันอีเมล + เข้าสู่ระบบ
2. ลงคอนเทนต์: ข่าว/บทความ/อัลบั้มภาพกิจกรรม
3. สร้างกิจกรรม + เปิด/ปิดรับสมัคร (จำกัดจำนวนที่นั่ง)
4. สมัครเข้าร่วมกิจกรรม + ยกเลิก
5. แจ้งเตือนสมาชิก: ประกาศกิจกรรมใหม่, เตือนล่วงหน้า 3 วัน/1 วัน,
   ยืนยันการสมัคร, แจ้งเลื่อน/ยกเลิกกิจกรรม (ผ่าน Email / Web Push / LINE)
6. หน้าตั้งค่าการแจ้งเตือนของสมาชิก (เลือกช่องทาง + หมวดที่สนใจ)
7. หน้า admin จัดการโพสต์/กิจกรรม/สมาชิก

## 4. Non-goals (เฟสนี้ยังไม่ทำ)
(เช่น ระบบชำระเงิน, multi-language, mobile app แยก)

## 5. ข้อจำกัด/บริบทสำคัญ
- ผู้ใช้ 80% เข้าผ่านมือถือ → mobile-first
- ข้อความ UI ทั้งหมดเป็นภาษาไทย
- เก็บข้อมูลนักศึกษา (ชื่อ, รหัสนักศึกษา, เบอร์โทร, อีเมล) → ต้องระวังความปลอดภัยเป็นพิเศษ
- งบประมาณจำกัด → ใช้ free tier ของ Vercel/Supabase ให้ได้นานที่สุด

## 6. Success metrics (ถ้ามี)
(เช่น จำนวนสมาชิกที่สมัคร, อัตราการเปิดอ่านอีเมลแจ้งเตือน)
